# Implementation Plan: 亲戚称呼计算器 UI 升级

## Overview

这是一个微信小程序，三页完成一件事：点出或打出一条亲戚链，立刻得到「你该叫他 / 他该叫你」。现有视觉已经是纸色底（`#F6F5F2`）加朱砂强调（`#B04A3A`），不该换成另一套通用风格。这次升级只改信息层级、触控和长文排版，称呼计算、查询参数和存储格式保持不变。

## 现状

首页把性别、关系链、键盘、文字输入、主按钮、最近记录做成五张权重相同的卡片。真正的循环是「点下一级 → 看称呼」，但预览藏在链卡片里，主按钮在输入框下面，选完键往往要往回滚。文字输入和点选并列，第一次使用要同时理解两套入口。点选非法关系时，警告写在输入框下方，离触发点很远。长幼确认出现后键盘仍可点。

结果页主称呼固定 `104rpx`、字距 `8rpx`。两三个字好看，逐级描述（没有专门称呼时）会挤爆。「他该叫你」再用 `64rpx`，和主答案抢视线。路径是一条要横滑的细节点。

关于页是八张同样式长文卡片，扫读成本高。

另外：`app.wxss` 里的 CSS 变量进不了组件（组件样式隔离），各页把同一套色值写死。底部按钮没有安全区。「删一步 / 清空」、chip 上的关闭符号热区偏小。`assets/logo/` 里的两张图约 1.5MB，页面没有引用，这次不用。

## Architecture Decisions

- 保留现有纸色和朱砂色，以及现有文案语气。升级的是结构，不是换品牌。
- 不改 `core/` 的计算、`toQuery` / `fromQuery`、最近记录的存储字段，也不改组件事件名（`pick`、`remove`、`undo`、`clear`）。
- 首页主表面是键盘。文字解析收成「直接打字」，默认收起。
- 关系链、当前称呼和「查看称呼」在常见手机高度上同时可见。主按钮固定在底部，留出安全区。
- 警告跟在触发它的控件旁边：点选错误靠键盘，解析错误靠输入框。
- 出现长幼确认时，键盘视觉上让位，先完成二选一。
- 结果页只有一个主称呼。短称呼保持大字，超过 6 个字改成正文级排版。反向称呼和路径是辅助信息。
- 关于页原文不改，只改成可折叠段落。
- 颜色和字号收进 `styles/tokens.wxss`，页面和组件各自 `@import`。微信组件拿不到页面上的 CSS 变量，不能只写在 `page` 上。

## Risks and Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| 底部固定栏挡住输入法 | Med | 输入框聚焦时取消固定，或把输入区滚进可视范围 |
| 改 `index.js` 的数据结构弄坏冒烟测试 | High | 不改 `preview`、`pending`、`warn`、`chips` 的含义；新状态只用新增字段 |
| 长称呼缩小后和短称呼看起来像两个产品 | Med | 只改字号和字距，颜色和位置不变 |
| 组件 `@import` 后和页面 token 漂移 | Low | token 只维护一份，组件禁止再写新的色值 |
| 折叠关于页让原有解释更难找到 | Med | 默认展开「怎么用」，其余标题保持原文 |

## Open Questions

- 无。文字输入默认收起、不用 logo、不换色，都按上面的决定执行。若要改方向，在首页检查点提出即可。
